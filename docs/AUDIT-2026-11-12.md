## Findings, worst first

### 1. The live site is behind the repository (correctness, blocks every fix below)

`/roadmap`, `/changelog` and `/planning-approvals` return **404** on
`freluxtools.com` while existing in the repository, so the hours of work shipped
on 11 and 12 November are not public. `/admin`, `/admin/travel-approvals`,
`/messages` and `/escrow` answer 200 by serving the single page shell, which
means those routes exist only for the JavaScript bundle, not for a crawler.

Cause is known and deliberate: Netlify auto build is switched off by the owner,
so nothing deploys without a manual build. Nothing in the repository can fix
that; it needs a deploy.

### 2. 125 of 151 calculator pages have no share and no PDF (completeness)

`ShareEstimateButton` is the component that carries WhatsApp share and Save PDF.
26 top level pages import it. 151 exist. So 125 calculators cannot share a result
or export it, against the standing instruction that every calculator and
estimator offers both.

### 3. Pricing is populated but almost entirely unverified (completeness, credibility)

`estimation_prices` holds 1,988 rows:

| Status | Rows |
| --- | --- |
| reported | 1,402 |
| unverified | 582 |
| verified | 4 |

Four verified rows out of 1,988 is 0.2 percent. Every claim of verified local
pricing outside those rows is currently unsupported.

### 4. The marketplace has no inventory (completeness)

`marketplace_listings` 0, `marketplace_bids` 0, `marketplace_orders` 0,
`cross_state_approvals` 0. The marketplace, escrow checkout and the new travel
approval screen are built, wired and empty. Nothing about them can be proven
correct against live data until a real listing exists.

### 5. Row level security gaps (security, defence in depth)

Six public tables have RLS disabled: `catalogue_products`, `material_categories`,
`material_aliases`, `catalogue_sync_requests`, `site_health_probes` and
`price_index_repair_snapshot`. Five of them carry INSERT, UPDATE and DELETE
grants for `anon` and `authenticated`. The anonymous probe is refused today, so
this is not an open door, but the only thing standing between a signed in user
and deleting a catalogue is a grant that already exists in
`information_schema.role_table_grants`.

Separately, 38 tables have RLS enabled with no policy at all. Those are readable
only by the service role, which may be intended for internal tables and is a
feature bug for anything a signed in user is meant to see.

### 6. Functions with JWT verification off need their own gate (security review)

48 of 83 deployed functions run with `verify_jwt = false`. Webhooks must, so the
list is not a defect in itself. Sampled individually: `spend-ai-credits`,
`award-credits`, `redeem-reward`, `record-activity`, `send-email` and the AI
functions do call `auth.getUser`. Five do not:

- `grant-rewarded-unlock` and `verify-rewarded-ad` never grant anything by
  design, so they are safe, and that is also finding 7.
- `iot-ingest`, `project-evidence-link` and `support-chat` have no user lookup.
  Each needs its own documented authentication story before it is trusted.

### 7. The rewarded credit economy cannot pay out (completeness)

`grant-rewarded-unlock` returns `success: false` with
`SERVER_VERIFICATION_NOT_CONFIGURED` for every provider, and
`verify-rewarded-ad` refuses on the same principle. That refusal is correct
security, but the practical result is that the 5 credits per ad cannot be earned
through these paths, so the economy depends entirely on the ayeT postback
(`ayet-rewarded-callback`) being configured.

## Not verified, and why

- **The full test suite.** Two bounded runs each exceeded five minutes without
  reaching a summary, and one showed a failing marker mid run. There is no count
  of passing tests and no list of failures from this audit, so no claim is made
  about suite health. The targeted suites for today's work (23 tests) pass.
- **Production build.** `npm run build` was started and had not finished its
  first typecheck pass inside the window; no bundle output was produced or
  checked, and the bundle budget script was not run.
- **Browser, accessibility, mobile and E2E passes.** `audit:ux`,
  `audit:mobile`, `e2e` and the Lighthouse config exist and were not run.
- **i18n coverage.** `i18n:coverage` exists and was not run.

## Suggested order

1. Deploy. Everything else is invisible until the live site matches `main`.
2. Wire `ShareEstimateButton` into the 125 calculators that lack it.
3. Enable RLS on the six tables and review the 38 policy-less ones.
4. Decide the rewarded provider, or stop advertising ad rewards.
5. Give `iot-ingest`, `project-evidence-link` and `support-chat` an explicit
   authentication story.
6. Get the test suite under a five minute run so it can be run per change.
