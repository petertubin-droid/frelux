# Site-wide UX completeness and correctness audit

Run 2026-11-11 against the FRELUX web app. The audit is executable, not a one-off
read: `node scripts/audit-ux.mjs` walks the router, resolves each page's rendered
component tree (so a feature shipped by a shared shell counts for the page that
uses it), and fails the build when a hard rule breaks. `--json` gives the machine
report, `--only=<text>` narrows to matching routes.

## What the site ships

| Measure                            | Value |
| ---------------------------------- | ----- |
| Routes                             | 364   |
| Routed pages                       | 298   |
| Routes that are legacy redirectors | 112   |
| Page files in `src/pages`          | 149   |
| Calculators and estimators audited | 39    |

## Rules checked

1. Ad density: at most 2 distinct placements on a calculator page, 3 on a long page.
2. No advertisement container renders an empty slot or a bare "Advertisement" label.
3. Every calculator offers WhatsApp share and PDF export under the FRELUX SMART CALC header.
4. Every calculator has a start-over control that resets page inputs only.
5. Every calculator states an estimate disclaimer and a "how this is calculated" note.
6. Every calculator has a mounted page test.
7. No em dash or en dash in shipped copy (reported, not enforced: see below).
8. Internal links resolve to a route.

## Findings

### Compliant

- Ad density: 0 pages over cap after the shared-shell placement keys are deduplicated. The earlier
  count of 35 over-cap pages was an artefact of counting the same slot key once per component in the tree.
- Empty ad containers: 0. Every placement hides when the central ad configuration has no provider,
  and no page hard-codes an "Advertisement" label.
- PDF export: present on all 39 calculators.
- Estimate disclaimer: present on all 39 calculators.

### Dashes: measured, not yet fixed

139 en and em dashes sit in shipped UI copy across 96 page and component files, plus more in library
comments and technical strings. A mechanical sweep was attempted and reverted: replacing the characters
is trivial, but 48 mounted page tests assert exact copy, so a blind pass turns green tests red and hides
real regressions. The cleanup needs one pass per file with its test updated alongside. Until then this
audit reports the dashes and does not enforce the rule as a hard failure.

The 20 dashes that must stay are the ones inside regular expressions and CSS class strings, where the
character is code rather than copy.

### Closed this pass

Every calculator now mounts all three actions, and the audit reports zero missing share, PDF, start over,
disclaimer, methodology note and mounted test across the 39 calculators.

- WhatsApp share added to `MarginCalculator`, `ConversationalEstimator` and `BoqGenerator`, each building
  its own snapshot from the result the page already shows.
- Start over added to those three plus `VisualFinishingEstimator` and `SmartCalculator`, whose resets clear
  media, surfaces, calibration and the finished estimate together rather than leaving a priced panel behind
  an empty photo. `BuildToRoofEstimator` already had a confirmed start-fresh flow; the audit now recognises it.
- "How this is calculated" added to all five, with new methodology entries for `margin`, `conversational`,
  `boq` and `smart-calc`. These state what the page does not do as well as what it does: the margin page
  reports its basis, the conversational page lists what it could not read, the BOQ keeps each line's source,
  and the smart calculator says plainly that it routes a job rather than pricing it.

Detection in `scripts/audit-ux.mjs` was tightened at the same time, because two real affordances were being
reported as missing: a page whose note is spelled `methodologyText` and one whose reset says "Start fresh".
Both now match, and the checks are case-insensitive where the copy legitimately varies.

### Open

1. `src/pages/ConfigurableFinishCalculator.tsx` is reachable from no route and imported by no page. It needs
   either a route and a sitemap entry or deletion; routing a new public URL is an SEO decision, so it stays
   unrouted until you choose.
2. 13 page files are mounted by their own sub-area layout rather than the main router
   (`market-intelligence/*`, `intelligence/IntelligenceDashboard`). Valid, but the audit cannot see their ads
   or actions from the route table, so they are outside the ad and share gates.
3. Two routes resolve only through parameterised paths: `/projects/:id` and `/site-tracker/:projectId`.
   The audit flags them as broken because it matches literal strings; they are not.
4. 112 legacy redirectors are treated as redirects rather than pages and are not individually reviewed.

## Correctness spot checks

- Currency and units render through the shared helpers (`formatCurrency`, `useDisplayCurrency`); no page
  writes a hard-coded symbol in an estimate.
- The painting estimator keeps its room-based input model: no customer-facing m² field, feet first with
  metric optional, 20 L purchase unit, 2 coats.
- Ad providers are read from one central configuration. No page carries a per-slot provider choice.

## Next

The share, reset and methodology gaps are closed and gated. What is left is dash cleanup in copy, the
`ConfigurableFinishCalculator` routing decision, and extending the audit's line of sight into the sub-area
layouts so their pages are held to the same ad and action rules.
